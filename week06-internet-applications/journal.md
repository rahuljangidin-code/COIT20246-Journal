## Task 4 – Analyse HTTP Packet Capture

### (a) HTTP Request and Response Explanation

- The first HTTP request occurred when the browser accessed the main page.
- A second request was generated when the link to the new HTML page was clicked.
- Additional requests occurred when the browser fetched supporting files such as the CSS file.

Each request was followed by an HTTP response from the web server delivering the requested resource.

### (b) Five Address Values Identified
1. Source IP address
2. Destination IP address
3. Source port number
4. Destination port number
5. Protocol (HTTP over TCP)

### (c) Button Click Behaviour

When the date and time button was clicked, no new HTTP request was sent to the server. This is because the button action is handled locally by JavaScript running in the browser.

### (d) HTTP Packet Diagram

A packet diagram was created for the HTTP request for the newly created HTML page. The diagram shows:
- Ethernet header
- IP header
- TCP header
- HTTP request data
- Total packet size

Both image and original drawio files have been uploaded.

### (e) Referrer Value

The referrer value identifies the web page from which the request originated. Web servers can use this information to analyse traffic sources and user navigation behaviour.

### (f) Browser Information

The server learned information about the browser such as:
- Browser name
- Browser version
- Operating system

This information is provided through the HTTP User-Agent field.

### (g) HTTP and Transport Protocol

- HTTP version used: HTTP/1.1
- Transport protocol used: TCP

### (h) Connection Setup

The TCP three-way handshake packets were identified as the connection setup phase. Data transfer began after the handshake completed.

### (i) Acknowledgements

TCP acknowledgements are sent to confirm successful receipt of data. They are typically sent after receiving data segments.
